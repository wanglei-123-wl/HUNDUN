# 远端玩家喝药动画

Gate 在有效的首次回血或回蓝用药后推送 `player_drink_event`。旁观客户端只处理动画，本人的喝药继续由 `item_use_result` 驱动。服务端字段见 GameServer 文档 341。

- 派发器在世界加载和切图期间直接丢弃此消息。接收时校验消息、连接、场景、收件人的场景会话，以及远端角色当前可见修订（包括合法的 0）。只查询已经生成的远端角色。
- 由进场快照和心跳建立服务端时间估算。至少已过去 1 秒的动作及尚未建立时钟时收到的动作会被丢弃。一次动作只处理一次，退出、世界切换和断线清空当前记录。
- 存活、落地且处于移动动画组的角色使用已有的 `Base Layer.吃药动画`，包括站立、走路和跑步。该状态沿 Animator 现有过渡返回活动状态。动作只影响视觉 Animator。
- 男修士及男修士 2 共用带有该状态的基础控制器。寒冰和 character_003 的控制器缺少相应状态，接收时跳过。


## 本地验证

- 用 Unity 2022.3.62f1 编译客户端运行脚本，现有用药及远端施法五项回归通过。
- 隔离 Unity 播放场景通过真实本机 Gate TCP 验证。站立回血和跑动回蓝分别触发旁观动画，本人原用药动画回调仍能播放。重复请求、冷却拒绝、纯修为、晚进入视野、旧会话、前后可见修订、过期、加载期间及空中动作均按预期处理。验证了男修士 2 的覆盖控制器和缺少该状态的寒冰控制器。
- 完整游戏客户端双开和云端联调待验证。
