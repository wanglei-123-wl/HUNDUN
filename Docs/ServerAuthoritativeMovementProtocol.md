# 移动事件 V2

HUNDUN 首次进场和重连发送 `movementProtocolVersion=2` 与 `movementBroadcastVersion=2`。客户端验证 Gate 回包的两个版本、场景会话、移动控制点和策略，确认控制点后开放普通移动。Gate 返回进场版本错误时立即显示原因。`docs/333-移动事件V2服务端与客户端接口.md` 说明移动控制和业务引用。服务端 [340 普通翻滚旁观者同步](../../../gameserver/docs/340-普通翻滚旁观者同步.md) 说明当前广播格式。

- Unity 用 `CharacterController` 按服务端提供的碰撞体尺寸、移动速度和跳跃参数在本地移动。起停、走跑、转向、起跳、落地及碰顶时发送单条 `movement_event`。持续运动默认 500ms 补一次当前位置，静止不发送移动心跳。松键在本帧结束普通位移。键盘和相机按帧读取，移动消息只随事件或移动心跳发送。
- 普攻、技能、拾取、攻击模式、背包和装备地面丢弃、传送查询与请求，通过同一 TCP 在当前位置事件后发送。请求携带场景会话、移动代次和最近发出的序号。移动前置检查拒绝后按业务序号规则重新操作。
- 冲刺、传送、复活和下落恢复使用服务端控制点。受控期间停止普通上报，按新的场景及代次确认后恢复。自身普通移动只对服务端纠正重新定位，旁观者按可见代次和移动修订号采纳新状态。
- 已学习且服务端标记自身目标的技能由技能栏以本角色为目标发送，位移类技能的实际位移由 Gate 推进。双击方向键沿用现有普通翻滚操作。
- `player_input` 和输入回放已移除。进场不接受旧移动协议。应用层会话心跳仍独立维护 Token 和连接。

站立原地右键转向只更新朝向，不执行 `CharacterController.Move`、下压落地探测或地图位置回退。连续鼠标采样合并为持续转向，鼠标目标短暂停顿不会逐帧发送起停；转向状态切换按服务端 `maxEventsPerSecond` 限制频率，该发送时钟在位置纠正换代后继续保留。松开右键、UI 阻断或进入行走时立即结束原地转向。空中的原地转向仍执行重力及碰撞处理。

本地模型通过 `LocalPlayerVisualGrounding` 的独立展示节点对齐脚底。原有光圈贴地和碰撞体落地不等于模型鞋底对齐；新节点在站立的 Locomotion 姿势按实际蒙皮鞋/脚网格校准基准，缺少可测网格时使用 Avatar 脚底高度回退。保留模型预制体原缩放。落地时检测当前地图地表并平滑补偿展示高度，腾空时使用模型的中性脚底基准；网络坐标、碰撞体与相机跟随节点保持独立，施法挂点及玩家特效跟随展示节点。这是模型整体的脚底基准校正，台阶上双脚分别贴合仍属于独立脚部 IK。

## 本地坐标显示

WorldShell 的“坐标”文本挂载 `LocalPlayerCoordinateTextPresenter`，保留原坐标节点和文字样式。显示格式为 `X（整数）Z（整数）`，使用全角括号，数值四舍五入，保留负号，不显示 Y。本地角色尚未就绪、断线或切图期间显示 `X（--）Z（--）`。

读取本地玩家移动逻辑根节点的 Unity 世界坐标；该坐标由现有移动、地图通行校验和服务端纠正共同维护。地图烘焙数据用于通行和支撑面判断，无需再次从烘焙数据推算玩家坐标。模型脚底补偿、动画和视觉平滑节点不作为显示位置来源。

首次就绪、重新启用显示或更换角色/场景会话时立即显示当前位置。之后以最后一次刷新时的原始 X/Z 为基准，仅当水平直线位移严格大于 1 个 Unity 单位时更新文本并重置基准；小于或等于该距离不刷新。比较发生在四舍五入之前，不把基准逐帧更新，因此小步持续移动最终也会触发刷新。Y 方向的变化不计入刷新距离。本功能只更新 UI，不增加请求或改变移动及上报逻辑。

## 锁定怪物后的自动接近

锁定怪物后发起普攻，距离不足时只记录这次待执行的攻击，自动跑向该怪物。目标技能同样先接近再发送施法请求；自身目标技能沿用直接施放。技能距离读取当前已学习技能快照的 `progress.attributes.range`，跟随快照更新。普攻距离由 `LocalPlayerCombatController.basicAttackRange` 配置，初始值对应当前本地后端 `Game.BattleCore/Combat/BattleCombatOptions.cs` 的 `basic_attack.Range`；运行服修改该配置时，客户端也需要同步。水平距离和目标高度差的判定沿用当前服务端规则，并在范围边缘留出小幅停止余量。缺少技能距离数据时保留原有发送流程，由服务端裁决，不推测追击距离。

自动接近在 `LocalPlayerInputController` 中转换为正常的前进、跑步方向，复用 `UpdateMovement`、地图通行检查、碰撞处理、起停和朝向事件及策略心跳。没有单独的移动消息或上报定时器，也不直接改角色位置。进入范围后先通过现有移动流程停下，经过原有停止攻击门禁后，再发送普攻或技能。普攻只有真正发送成功才预测攻击动画；追击期间不递增战斗请求序号、不提前进入技能冷却。每次操作只执行该次攻击，不自动连续攻击。

手动按键、鼠标按下、滚轮、右键转向、UI 操作、跳跃、翻滚、打坐、换目标会取消之前的追击；新的攻击指令可替换待执行指令。目标死亡或消失、断线、切图、禁用输入和收到新的移动控制代次也会清理追击。取消后通过正常移动流程停止或接管方向，不保留稍后自动释放的旧指令。

当前追击沿目标方向前进，持续更新朝向；地图或碰撞阻挡、持续无法前进、无法接受的目标高度差会停止追击，不穿越障碍，也不新增绕障寻路。本次仅做脚本编译和静态核对，游戏效果由用户验证，不运行测试或打包客户端。

## 其他玩家的移动广播

`player_movement_event.data` 使用紧凑数组。普通地面为 14 项，空中和地面翻滚为 16 项。按空中位读取末尾两项，空中是竖直速度和跳速，地面翻滚是 64 位动作编号和已过毫秒数。Unity 按整数读取角色 ID、可见代次、移动代次、修订号及服务器时间。进场、进入视野和修复快照中的 `movement` 采用完整对象，当前翻滚携带可选 `roll`。

广播先匹配接收方场景会话，再按远端角色的可见代次和移动修订排序。先于角色建立到达的广播在现有缓存内等待。同一可见代次的完整快照与广播共用移动修订，旧快照不会重置已应用的新移动。Unity 与支持广播格式 2 的 Gate 配套发布和回退。

### 普通翻滚

- 本地通过双击方向键触发。Animator 实际进入 `Roll` 时上报 `roll_start`，退出时上报 `roll_end`。先发同一帧的走跑或起停事件，再随同一 TCP 的移动序号发动作事件。刹停仍允许模型播完翻滚。
- 旁观者按同一动作编号只播放一次。进视野时把服务端给的已过毫秒数用作实际片段的播放起点。角色根节点继续由网络位置与朝向驱动，动画根运动关闭。
- 下落、死亡、切换移动控制、切图或离开视野时清理动作。男修士复用已有翻滚片段，寒冰和 `character_003` 的状态机目前缺少适配各自骨架的翻滚动作。

Unity 脚本编译及隔离播放模式通过。本地新版 Gate 与三条真实 TCP 连接验证双击输入、走跑与翻滚顺序、刹停后继续播、晚进入视野、死亡与移动代次清理，使用项目的男修士控制器、骨架及翻滚片段。正式游戏双开画面与云端待联调。

## 怪物字段增量与路径

HUNDUN 进场请求 `monsterSyncVersion=2`。关闭怪物扩展的 Gate 仍使用完整状态帧。启用两项扩展后，Gate 回显版本 2，并给含怪物状态的帧附上收件人场景会话。版本不匹配会在进场时报错。服务端协议见 `docs/337-怪物字段增量路径广播与场景并行.md`。

- 按场景会话、怪物网络 ID、可见代次和怪物自己的基线帧序号合并位置、行为和血量。丢失基线时请求现有快照修复。移出视野、重生、换图、重连以及完整快照替换都会清理对应缓存。旧血量由战斗修订过滤。
- 追击和返回收到短地面路径后，按服务器起始时间计算播放进度，到终点停止推进。收到改道、停止、偏差较大的坐标校正、攻击或死亡时，立即停止沿旧路径推进。新进入视野和修复快照可以带当前路径，坡路和空中状态继续采用服务器位置。

本地已通过 Unity 脚本编译、真实回环 Gate 帧解析、字段基线与较新血量保护、路径进度与停止、进场及切图回归。Unity 游戏画面和云端待配套验收。

## 怪物死亡碰撞体

`MonsterNetworkView` 收到服务端 `Dead` 状态，或在已知最大血量时确认当前血量归零，会立即关闭该怪物根节点及所有子节点的 3D 碰撞体，包含非激活子节点，不等待死亡动画结束。碰撞体组件保留，尸体模型和死亡动画继续展示。

关闭前逐个记录碰撞体原有的 `enabled` 状态；存活状态重新初始化、血量从零恢复为正值或显式 `ResetView` 时恢复这些状态。原本关闭的碰撞体仍保持关闭，重复死亡通知不会覆盖最初记录。状态和战斗修订仍由原有同步流程过滤。

## 客户端地图通行约束

`WorldMapLayerLoader` 在进场时准备当前地图的通行数据，`GameSession` 在切图时更换查询。当前地图未就绪时不开放本地输入。数据来源和校验值记录在 `MapTraversalStage2Import.json`，资源包地址为 `game/map-traversal/{mapId}`，构建版需要重建并分发对应 Addressables 资源。

`PredictedCharacterMotor.MapTraversal.cs` 在每段普通位移执行前，使用移动控制点下发的半径和高度查询整段路径。地面移动使用后端导入的支撑面、碰撞体和通行算法；旧版地图沿用后端移动使用的 walkable 检查。不能整段通过时，搜索仍能通过的前缀，不做跨角点的横纵轴拆分。Unity 碰撞处理后的实际位置也再次校验，防止滑动或重叠恢复把角色推到禁止区域。跳跃和下落使用胶囊体扫掠，并保留落地、碰顶事件。

走路、跑步和普通翻滚共用这条通行检查。地面手动走跑可以在障碍前减速沿安全方向滑行，具体见下一节。没有可通过的方向时清除水平速度并发送 `stop`。同一位置持续按住被挡方向时保持停止，松键、转向、跳跃或位置变化后可重新尝试。停止发送失败时先重发，再处理后续移动和位置引用请求。诊断开启时输出 `local_traversal_blocked`，记录地图包校验值、请求位置、接受位置及角色尺寸。

技能冲刺、传送、复活及其他受控位移继续使用服务端控制点，不由本地通行查询改写。当前只能确认导入包和本地后端源码对应，尚未验证运行中服务端的数据版本；这不能保证消除所有服务端纠正。

### 地面手动滑行

- 手动走跑受阻后，复用当前地图的胶囊扫掠和地面支撑检查，在约 0.32 米内试探安全方向。有角色控制器的侧向碰撞时优先沿实际接触面，通过地图校验后才继续移动。保持选定的一侧，找不到短路径时停步。
- 滑行速度以当前跑速的一半为上限，并受步行速度限制。前方重新通畅后恢复当前按键的走跑模式。松开、改向、离地、死亡、切图和移动纠正会结束当前滑行。其中松键从本帧采样后停止，角色只积分已经过去的那段移动时间。
- 通过现有 `walk`、`run`、`facing`、`start` 和 `stop` 上报拐点、实际坐标和速度。方向改变先结算并上报旧路径端点，再沿新方向前进。北向附近的浮点角度归一到移动 V2 要求的左闭右开范围。

Unity 2022.3.62f1 编译与本地 Gate TCP 联调通过。隔离用例覆盖 V1 与 V3 地面、正碰石头、斜撞墙尾、内墙角、窄缝、悬崖边、松键和改向。最终七条路线的观察者收到 49 条移动广播，Gate 位置纠正为 0。GameServer 移动 V2 专项通过，正式游戏地图待实机验证。


本阶段按用户要求没有运行自动化测试或游戏场景测试，脚本编译检查单独进行。

## 构建地图通行资源

Unity 编辑器菜单：`Tools > Resource Update > Build Map Traversal Content`。该入口保持当前 Addressables Profile、分组和资源地址，先核对导入清单中的地图包与 SHA256，再构建当前配置的完整资源目录。构建后检查地图包地址能否解析到生成的 Bundle，并记录目录及地图 Bundle 的文件校验值。结果写入 `Docs/MapTraversalStage4Build.json`；只有 `status` 为 `succeeded` 才表示构建及目录检查均完成。

若原生构建已完成、仅后续校验失败，可用 `Tools > Resource Update > Verify Map Traversal Content` 复核已有产物。此入口要求上一份报告记录原生构建成功，且配置、查询源码版本匹配，地图数据文件在该次构建后未修改；它不会重新打包场景或编译着色器。自动化工具可向 `Temp/MapTraversalContentVerify.request.json` 提交同样格式的一次性请求。

编辑器未占用项目时，也可使用 Unity 的 `-batchmode -projectPath <项目绝对路径> -executeMethod MapTraversalContentBuild.BuildBatch` 执行同一入口，失败会返回非零退出码。编辑器占用项目时，需要在现有编辑器中触发菜单。自动化工具也可在 `Temp/MapTraversalContentBuild.request.json` 写入显式请求，字段为 `requestId`（无连字符 GUID）、`projectRoot` 和 `expiresAtUtc`；入口在导入后只领取一次有效请求，项目路径不符或过期请求不会执行。进入播放模式时不会自动退出播放或启动游戏测试。

本地资源构建不发布文件，也不构建客户端程序。构建版使用新逻辑还需要重新构建客户端；远程资源分发需包含生成的目录、hash 和目录引用的 Bundle。后端运行版本是否与导入数据一致仍需另行确认。

`RemoteWorldMaps` 按资源分别打包，地址中的斜杠会产生 Bundle 子目录。分发资源时需要保留这些子目录，不能只复制输出目录顶层的文件。

## 本地打坐条件特效

`Assets/Settings/玩家公共表现配置.asset` 保存共用显示规则，每条记录的特效名称同时作为稳定的唯一 ID。保留原有的“出场播放”和“按名称调用”，新增“条件控制”触发方式。显示条件目前支持“存活”和“打坐中”，勾选的条件必须同时满足；不勾选条件保留原有无条件行为。

`PlayerEffectStateSource` 挂在各自玩家根节点，保存该玩家的已知状态、存活和打坐状态，状态发生变化才通知 `PlayerEffectPresenter`。共用的配置资源不保存角色运行状态。条件控制自动启动和关闭特效；出场、手动调用也必须通过同一条件检查，条件失效会停止已播放的效果。循环特效不会重复创建；条件控制的一次性特效在每次条件由不满足变为满足时播放一次。

当前 `MeshFX_Galaxy` 设置为“条件控制 + 循环播放 + 存活 + 打坐中”。本地和远端收到服务端打坐状态后，还需等待动画完整进入 `Base Layer.打坐中` 循环才显示；坐下及进入循环的过渡不显示，确认起身时立即隐藏。没有配套打坐动画的模型不显示光晕。停止时同时清理粒子和模型表面的覆盖光效。

打坐同步现已接入服务端坐姿、可靠消息和视野快照，详见 `PlayerMeditationProtocol.md`。输入锁持续到起身动画及其退出过渡结束；移动、跳跃、翻滚、普攻、技能和道具请求在锁定期间不生效，也不缓存补发。本次修改不构建资源或客户端。

## 玩家目标与自动追击

普攻和非自身技能可使用有效的怪物或远端玩家目标。锁定玩家后普攻距离不足，或者技能目标距离不足时，复用原有自动追击与移动事件流程；目标死亡、离场、改锁、会话变更、手动操作及道路受阻仍会取消追击。技能请求使用实际目标的 `targetType`，目标位置特效也支持玩家。

当前本地 GameServer 源码的 `BattleSkillCastHandler` 接受 `player` 目标，`BattleScene.TryResolveSkillTarget` 解析玩家，`CheckSkillPlayerAttack` 校验攻击许可。是否能命中仍取决于服务端的安全区、PvP、目标存活、技能目标类型和距离校验。本次只调整客户端，不修改后端；运行中的后端是否与该源码一致尚未核实。

## 构建 Windows 本地客户端

编辑器菜单 `Tools > Resource Update > Build Windows Local Trial Player` 或批处理入口 `WindowsLocalTrialPlayerBuild.BuildBatch` 使用当前 LocalTrial 配置构建 Windows 客户端。要求打坐资源构建记录成功且配置、源码、目录及世界场景依赖校验值仍然匹配。启动场景是唯一直接打入程序的场景，沿用已构建的 Addressables 内容，不切换资源环境或服务器地址。

每次输出到新的 `Build/WindowsLocalTrial/MeditationEffect-{requestId}/HUNDUN.exe`，避免覆盖旧程序。构建后核对程序内置的 Addressables 设置、本地目录和世界场景本地依赖，结果写入 `WindowsLocalTrialPlayerBuild.json`。此入口不启动客户端或运行测试；LocalTrial 的远程资源仍通过当前本地资源服务加载。

编辑器已打开时，可向 `Temp/WindowsLocalTrialPlayerBuild.request.json` 提交显式、一次性的请求，包含 `requestId`（无连字符 GUID）、`projectRoot` 和 `expiresAtUtc`。入口在编辑器停止播放且导入、编译完成后领取请求，过期或项目路径不符的请求会拒绝执行。
