# 玩家打坐的 Unity 接入

适用项目为 HUNDUN，服务端协议见 GameServer 的《玩家打坐服务端与客户端接口》（339）。

## 本人操作

- 按 Q 发送 `meditation_set`。跑动时先提交停止事件，再携带该场景最后发送的移动引用。Q 按下时已经按住的方向键或双鼠标移动组合，松开后才重新接管角色。
- 再按 Q 主动起身。新移动或跳跃操作只发起身请求；服务端确认后仍需等起身动画及其退出过渡完整结束，才能移动、跳跃、翻滚、普攻、施法或使用道具。期间的点击指令丢弃，不排队补发；一直按住方向键时，在站立后按正常移动流程起步。服务器心跳、起身确认及停止事件继续沿用原流程。
- 同一时刻只保留一个待确认的坐姿请求，持续按方向键不会逐帧发送新的起身请求。待确认请求的原序号、移动引用及重试上限沿用现有协议。旧结果和旧场景数据不覆盖当前坐姿。
- 坐姿取自服务端回执或可靠消息；光晕还需等动画完整进入 `Base Layer.打坐中` 循环后才显示。按 Q、坐下过程和进入循环的过渡均不显示，确认起身后立即关闭。本地和远端使用相同显示时序。
- 本人收到 `meditation_vitals` 后，用战斗修订更新现有生命值与灵力值数据源。血蓝显示沿用原 HUD。

## 其他玩家

- `meditation_state` 通过 BattleSync 现有可靠消息渠道确认。匹配同一场景会话及可见代次后才应用。先于角色出现的通知暂存到对应角色进入视野。
- 进场、切图及全量玩家快照携带同一坐姿字段。新进入视野时，支持打坐的角色直接显示打坐循环。旧坐姿修订、离场及不同场景的通知不会恢复旧姿势。
- 男修士使用已有的玩家状态机和打坐动作。寒冰及 `character_003` 使用各自的状态机，现有资源中缺少适配的打坐动作。没有打坐循环的模型不显示打坐光晕，需要补齐配套动作后才能显示。

## 验证

- 使用 Unity 2022.3.62f1 的编译参数编译全部客户端运行脚本。
- 早期接入曾进行隔离播放和回环 TCP 检查；它们不代表本次动画时序修改已经过游戏验证。本次仅做运行脚本编译及静态核对，不运行游戏、自动化测试或客户端打包，实际表现由用户验证。
