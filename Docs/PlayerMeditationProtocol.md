# 玩家打坐的 Unity 接入

适用项目为 HUNDUN，服务端协议见 GameServer 的《玩家打坐服务端与客户端接口》（339）。

## 本人操作

- 按 Q 发送 `meditation_set`。跑动时先提交停止事件，再携带该场景最后发送的移动引用。Q 按下时已经按住的方向键或双鼠标移动组合，松开后才重新接管角色。
- 再按 Q 主动起身。新移动或跳跃操作先发起身请求，再上报移动。成功攻击、施法、受伤等由 Gate 按已接受的操作判断是否结束打坐。
- 动作和特效取自服务端回执或可靠坐姿消息。待确认请求以原请求序号和移动引用最多重发两次。旧结果和旧场景数据不覆盖当前坐姿。
- 本人收到 `meditation_vitals` 后，用战斗修订更新现有生命值与灵力值数据源。血蓝显示沿用原 HUD。

## 其他玩家

- `meditation_state` 通过 BattleSync 现有可靠消息渠道确认。匹配同一场景会话及可见代次后才应用。先于角色出现的通知暂存到对应角色进入视野。
- 进场、切图及全量玩家快照携带同一坐姿字段。新进入视野时，支持打坐的角色直接显示打坐循环。旧坐姿修订、离场及不同场景的通知不会恢复旧姿势。
- 男修士使用已有的玩家状态机和打坐动作。寒冰及 `character_003` 使用各自的状态机，现有资源中缺少适配的打坐动作。这两种模型仍会按服务端状态显示和关闭现有打坐特效，模型坐姿需要配套动作资源。

## 验证

- 使用 Unity 2022.3.62f1 的编译参数编译全部客户端运行脚本。
- Unity 隔离播放模式检查真实回环 TCP 的请求及原序号重试，验证本人血蓝、只回蓝场景、旧修订和旧场景、可见前通知缓存、晚入视野的打坐循环、起身清理特效，以及没有打坐动画的模型仍显示特效。测试使用原玩家状态机和独立测试动作与特效。
- GameServer 的 `--meditation` 真实回环 TCP 专项通过。正式客户端双开画面和云端尚未联调。
